# 2026-09-09 工作记录

## Grok 情绪搜索延迟优化

- 将原先一次请求同时执行 X Search、Web Search 和归纳的流程，拆为 X 与网页两个并行搜索请求，再通过第三次无搜索工具请求合并结果，避免代理端串行搜索导致完整请求超过 `90s`。
- X Search 设置 `45s` 超时，Web Search 设置 `20s` 超时，最终合并设置 `20s` 超时；即使兼容代理走串行路径，最坏也会在 `85s` 内失败，两个搜索渠道必须同时成功，任何一段失败均不得形成交易确认。
- 当前兼容代理实测存在单账户并发限制，并行时会让两个搜索同时超时。原生 xAI 保留并行路径，兼容代理改为 Web→X 受控串行；两个搜索提示只要求来源与事实、各限制 `650` tokens，评分统一留给最终合并请求。任何渠道失败都不使用单渠道结果。
- 合并引用时按 X、网页交错保留并按 URL 去重，避免单一渠道占满引用上限。最终情绪报告仍只能采用搜索响应实际返回的 URL，原有来源数、置信度、连续确认和冷却门槛不变。
- 审计记录增加两个分渠道搜索响应 ID 和三段 usage，不记录 API Key。
- 增加渠道校验、引用交错去重和合并提示白名单测试；完成后需通过完整测试并做一次真实代理端到端请求。
